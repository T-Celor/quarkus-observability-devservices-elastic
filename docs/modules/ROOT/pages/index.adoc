= Observability Dev Services Elastic
:description: Quarkiverse extension that provisions an Elastic observability stack for Quarkus dev and test modes.

The `quarkus-observability-devservices-elastic` extension starts:

- Elasticsearch
- Kibana
- Elastic APM Server
- OpenTelemetry Collector

and, when OpenTelemetry is in the application, publishes a default `quarkus.otel.exporter.otlp.endpoint` for the host OTLP gRPC receiver.

It follows the same principles as the Quarkus Grafana LGTM dev service (`quarkus-observability-devservices-lgtm`): the same configuration shape, the same discovery order and the same launch-mode and Docker checks.

== Installation

[source,xml]
----
<dependency>
  <groupId>io.quarkiverse.observability</groupId>
  <artifactId>quarkus-observability-devservices-elastic</artifactId>
  <version>${project.version}</version>
</dependency>
----

== How it starts

. Nothing starts when Dev Services are disabled, when `quarkus.observability.elastic.enabled=false`, in test mode unless `quarkus.observability.elastic.enabled-in-tests=true`, or when no container runtime is available.
. `shared=true` (default, dev mode only): containers started earlier and carrying the extension labels are reused. The whole stack must be found; a partial stack is not reused.
. Services of a Compose Dev Services project are reused when they match the stack, by image or by service name (`elasticsearch`, `kibana`, `apm-server`, `otel-collector`). The extension does not generate or parse compose files: provide your own with `quarkus.compose.devservices.files` if you want Compose.
. Otherwise the four containers are started with Testcontainers and owned by Quarkus (started, restarted on live reload when the config changes, closed).

Host ports are free random ports unless you fix them with the `*-port` keys.

== Configuration

Prefix: `quarkus.observability.elastic`.

- `enabled` (default `true`)
- `enabled-in-tests` (default `false`, no effect in dev mode)
- `shared` (default `true`, dev mode only)
- `label` (default `quarkus-dev-service-elastic`, suffixed with the service name on each container)
- `service-name` (default `elastic`, value of those labels)
- `elasticsearch-image` (default `elasticsearch:9.5.5`)
- `kibana-image` (default `kibana:9.5.5`)
- `apm-server-image` (default `elastic/apm-server:9.5.5`)
- `otel-collector-image` (default `otel/opentelemetry-collector-contrib:0.164.0`)
- `otel-collector-config` (optional custom collector YAML file)
- `elasticsearch-port`, `kibana-port`, `apm-server-port`, `otlp-grpc-port`, `otlp-http-port` (optional: fixed host port when set, random otherwise)

The ports actually used are published to the application as `observability.elastic.{elasticsearch,kibana,apm-server,otlp-grpc,otlp-http}-port`, with `observability.elastic.host`.

Internal service-to-service links stay fixed:

- Kibana -> `http://elasticsearch:9200`
- APM Server -> `http://elasticsearch:9200` and `http://kibana:5601`
- OpenTelemetry Collector -> `http://apm-server:8200`

== Compose example

Reuse a stack you run yourself with Compose Dev Services. Name the services `elasticsearch`, `kibana`, `apm-server` and `otel-collector` (or use the default images) and publish their standard ports.

[source,yaml]
----
quarkus:
  compose:
    devservices:
      enabled: true
      files: ./src/main/compose/compose-devservices.yml
----

== Try it

Minimal application: `quarkus-rest`, `quarkus-opentelemetry` and this extension.

[source,properties]
----
quarkus.application.name=demo-app
# quarkus-opentelemetry also starts the Grafana LGTM dev service by default; disable it to keep only the Elastic stack
quarkus.observability.lgtm.enabled=false
----

Run `mvn quarkus:dev`, call an endpoint a few times (`curl localhost:8080/hello`), look for the Kibana port in the log (`Elastic observability Dev Services started, ... kibana=<port>`) and open `http://localhost:<port>` (Observability > Applications). The first start pulls the Elastic images, which can take several minutes.

== Testing

The extension provides:

- JVM mode test (`@QuarkusTest`)
- packaged mode test (`@QuarkusIntegrationTest`)

The tests set `quarkus.observability.elastic.enabled-in-tests=true` and include `quarkus-opentelemetry`. JVM tests validate stack endpoint reachability and OTLP endpoint publication. Packaged mode keeps config bootstrap validation without forcing container assertions.
